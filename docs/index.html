Mandarin DAC Bridge

Audirvana and Mandarin, sharing your USB DACs. The bridge holds each DAC exclusively, switches it to every track's own sample rate, plays the samples untouched, and offers it on your network as a UPnP renderer, so either app can play to it, but never both at once. Optionally also as a Squeezebox player, a Spotify Connect speaker (Spotify Soloist), a Qobuz Connect speaker (QobuzProxy) and a Plex player (Caldera Headless); on a Mac, the Music and Spotify apps play through it too. Beside Roon Bridge, with a now-playing screen. On macOS, Windows and Linux.

How it works

On a Mac, Audirvana takes a USB DAC in exclusive (hog) mode to switch its sample rate. While it holds the DAC, nothing else can see it, so Mandarin finds no DAC. The bridge takes each DAC itself, and offers it to both apps over the network.

Audirvanachooses "D90 (Bridge)"
Mandarinchooses "D90 (Bridge)"
→
DAC Bridgeone app at a time · port 55500
→
USB DAC 1exclusive · rate-switched
USB DAC 2exclusive · rate-switched

Whichever app starts playing owns that DAC. If the other app tries to change anything while it plays, the bridge refuses it (UPnP error 705, Transport is locked). The owner keeps the DAC for 10 seconds after it stops, so it doesn't lose it between tracks.

What it does

Nothing to set up. Plug a DAC in and it appears, on the page and on the network, within a few seconds.

🔒Exclusive, always

Each USB DAC is held whether it's playing or not, so no app can grab it behind your back. On a Mac that's Core Audio's hog mode; on Linux it's the ALSA hw: device, held open.

🎚️Bit-perfect, rate-switched

The DAC switches to every track's own rate: 44.1, 96, 192, up to 768 kHz. The samples reach it unchanged, and the track is resampled only when the DAC can't take its rate.

🦆One app at a time

Audirvana or Mandarin, whichever is playing, is in control. The other is kept out until it stops, and the page shows who has each DAC and who was kept out.

💿DSD as DoP

DSF and DFF files go to the DAC as DoP, untouched (DSD64 to DSD256). DoP is on automatically when a DAC reports native DSD; elsewhere, switch it on per DAC.

⏭️Gapless

When an app sends the next track ahead of time, a track at the same rate follows with no gap. A different rate plays out first, then the DAC switches.

📱A page per DAC

Open http://<machine>:55500 on any phone or computer: a tile per DAC, with its name and model. Tap one for its rates, depths, DSD and formats; the ✕ takes you back.

Install on a Mac

The easy way: one line in Terminal. macOS 14 or newer, macOS 27 included, Apple silicon or Intel. No Docker needed.

  1. Open Terminal: press Command-Space, type Terminal and press Return.
  1. Paste this line and press Return.
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/meltface-80/Mandarin-DAC-Bridge/main/tools/mac/install.sh)"
  1. Answer what it asks. Your Mac's password, if Homebrew needs installing (nothing shows as you type; that's normal). Allow if macOS asks to let mandarin-dac-bridge find devices on your network.
  1. Done. The page opens in your browser at http://localhost:55500 with a tile for each USB DAC. The bridge starts by itself whenever you log in. On a phone, open the address Terminal shows at the end.
What it installs: Homebrew (if missing) and ffmpeg, the same ones Mandarin uses, so nothing new if Mandarin is already on the Mac. Then the bridge itself, one program in ~/Mandarin-DAC-Bridge. To update, paste the same line again; your settings are kept.
Prefer to install by hand?

Download mandarin-dac-bridge-osx-arm64.tar.gz (Apple silicon) or -osx-x64 (Intel) from the latest release, then:

brew install ffmpeg
mkdir -p ~/Mandarin-DAC-Bridge
tar -xzf ~/Downloads/mandarin-dac-bridge-osx-*.tar.gz -C ~/Mandarin-DAC-Bridge
~/Mandarin-DAC-Bridge/mandarin-dac-bridge --list    # the DACs it can see
~/Mandarin-DAC-Bridge/mandarin-dac-bridge           # run it; Control-C stops it

Install on Windows

Windows 10 or 11, x64 or ARM64. One line in PowerShell. The bridge holds each USB DAC in WASAPI exclusive mode, so Windows' mixer never touches the samples.

  1. Open PowerShell: right-click Start and choose Terminal (or Windows PowerShell).
  1. Paste this line and press Enter.
powershell -ExecutionPolicy Bypass -c "irm https://raw.githubusercontent.com/meltface-80/Mandarin-DAC-Bridge/main/tools/windows/install.ps1 | iex"
  1. Allow if Windows asks to let mandarin-dac-bridge use the network (private networks).
  1. Done. The page opens at http://localhost:55500. The bridge starts by itself at every sign-in.
What it installs: ffmpeg (with winget, if it isn't there) and the bridge, one program in %LOCALAPPDATA%\Mandarin-DAC-Bridge, started by a hidden scheduled task. To update, paste the same line again; your settings are kept. In Sound settings, the DACs the bridge holds show as in use: that's the exclusive hold. Windows' own sound goes to another output.

Install with Docker

On an always-on Linux machine with the DACs plugged into it: DietPi on an Intel i5, a NUC, a Raspberry Pi 4/5 on a 64-bit OS. Choose docker run or docker compose, fill in what you need and copy the command. Docker builds the bridge from this repository the first time.


      

      


      
--network host is required. Audirvana and Mandarin find the bridge by multicast,
        which doesn't cross Docker's bridge network. Docker Desktop for Mac and Windows has no real host networking:
        on a Mac, use the one-line install.

      
The sound devices. --device /dev/snd, --privileged and
        -v /dev/snd:/dev/snd work together: the first hands the sound devices to the container,
        the second lets it open them, and the mount keeps the list current, so a DAC plugged in later is
        found too. Leave out any of them and the DACs may not appear.

      
Mandarin on the same machine? If its container has --device /dev/snd,
        switch off its local output for the DACs (Settings → Audio Devices), so the bridge can hold them.

Audirvana

        
Output: the Bridge, over UPnP

        
Settings → Audio → choose "<DAC> (Bridge)" in the UPnP list, not the DAC itself.
          While Audirvana still holds the DAC directly, its tile on the bridge's page says Waiting · Audirvana
          has the DAC. The bridge takes the DAC the moment Audirvana lets go of it.

      

      

        
Mandarin

        
A zone like any renderer

        
Settings → Audio Devices → choose "<DAC> (Bridge)". If Mandarin's own local output for that
          DAC is switched on, switch it off: the bridge owns the DAC now. Volume stays at 100% for bit-perfect
          playback; use the DAC's or amplifier's volume.

      

    

  






  

    
More ways to play

    
UPnP is always on. These are optional, and go through the same exclusive, rate-switched path and
      the same one-app-at-a-time rule: whatever is playing keeps the others out until it stops.

    

      

        
Squeezebox · squeezelite

        
Lyrion Music Server, and Roon

        
Switch on Squeezebox under Connections on the bridge's page. Each DAC then becomes a player,
          "<DAC> (Bridge)", for Lyrion Music Server (LMS) — and for Roon, with Settings → Setup → Squeezebox
          support on. The bridge speaks the Squeezebox protocol itself rather than running squeezelite, because
          squeezelite would need the DAC to itself. The server is found by itself; type its address if it isn't.

        
FLAC, PCM, AIFF, MP3 and Ogg are taken as they come, gapless. DSD is converted by the server. In LMS, set
          the player's volume control to fixed at 100% for bit-perfect playback.

      

      

        
Spotify Connect · Linux

        
Through Spotify Soloist

        
Spotify Soloist is Spotify's own Spotify
          Connect client for Linux. Switch on Spotify Connect on the bridge's page and each DAC appears in the
          Spotify app's device list. It needs:

        
· Your own Soloist API key, made at Spotify
          for Developers (needs Premium), typed on the page. It is never shown again.

          · Soloist, which may not be passed around: Download Soloist on the page fetches Spotify's own
          build for the machine. A build lasts 90 days; the page shows until when.

          · Linux with glibc 2.38 or later (Debian 13, Ubuntu 24.04, Raspberry Pi OS trixie), or the Docker
          image on anything older. There is no Soloist for macOS.

          · PulseAudio (sudo apt install pulseaudio; in the Docker image already).

        
Soloist plays into a private PulseAudio with no sound card, only a pipe the bridge reads, so its sound takes
          the same exclusive path as everything else, at 44.1 kHz, paced by the DAC: nothing is resampled. If another
          app has the DAC, Spotify is paused. The volume stays at 100%.

        
Soloist takes the key only on its command line, so other accounts on the same machine could read it from
          the process list; on a machine you share, run the bridge in Docker. On a Mac, the Spotify app itself plays
          through the bridge instead (below).

      

      

        
Qobuz Connect · Mac, Windows, Linux

        
Through QobuzProxy

        
Switch on Qobuz Connect on the bridge's page, press Install QobuzProxy (it fetches
          QobuzProxy into a private Python environment; Python 3.10
          or later must be on the machine, and is in the Docker image), then Sign in to Qobuz on QobuzProxy's own
          page. Each DAC then appears in the Qobuz app's device list, as "<DAC> (Bridge)".

        
QobuzProxy speaks Qobuz Connect and hands each track to the DAC's UPnP device, so Qobuz plays through the
          bridge like Audirvana does, in hi-res up to the DAC's best rate, under the same one-app-at-a-time rule.

      

      

        
Plex · Linux

        
Through Caldera Headless

        
Switch on Plex · Caldera Headless on the bridge's page, press Download Caldera (from
          Caldera), then Sign in to Plex: the page shows a
          code to enter at plex.tv/link. Each DAC then appears as a player in
          Plexamp, Plex for iOS and the Plex web app.

        
Caldera plays to the DAC itself, bit-perfect. The bridge shares the DAC with it: whoever plays first has it,
          and the other waits. What Caldera plays shows on the DAC's page and on the now-playing screen.

      

      

        
This Mac · Apple Music & Spotify

        
The Music and Spotify apps, bit-perfect

        
Neither app can play to a DAC the bridge holds, or switch its rate per track. So, as
          Arco does for Roon, a small virtual output,
          DAC Bridge, is the Mac's output while this is on: the app plays to it, and the bridge plays the same
          samples to the DAC you choose, at each track's own rate (Spotify at 44.1 kHz), with the virtual output's clock
          following the DAC's. Install the output once (your password; the Mac's sound stops for a few seconds):

        


/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/meltface-80/Mandarin-DAC-Bridge/main/tools/mac/driver.sh)"
# remove it again:  … driver.sh)" -- --remove

        
Needs Apple's command line tools (it offers to install them). Then switch on This Mac: Apple Music &
          Spotify on the bridge's page. The first time, macOS asks to allow Microphone access: that is how the
          bridge reads the DAC Bridge output (it never listens to a microphone). Switched off, the Mac's output goes
          back to what it was.

      

      

        
Roon Bridge

        
Beside the bridge, sharing the DAC

        
Roon Bridge can't be bundled (Roon's licence), and Roon Ready playback (RAAT) is Roon's own, so Roon Bridge
          runs next to the bridge. Like RoPieee, this downloads Roon's own installer from Roon Labs and runs it:

        


/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/meltface-80/Mandarin-DAC-Bridge/main/tools/linux/roon-bridge.sh)"

        
On a Mac, install Roon Bridge for macOS.
          Then, on each DAC Roon should use, switch on Share when idle: the bridge lets go of the DAC whenever
          nothing plays through it, so Roon can take it, and takes it back when an app plays to the bridge (once
          Roon has let go). Or skip Roon Bridge: Roon's Squeezebox support plays to the bridge directly, with Roon's
          Squeezebox limits.

      

      

        
Now-playing screen

        
A monitor beside the DAC

        
Open http://<machine>:55500/now full-screen on any screen: cover,
          title, artist, album, time and format of what's playing, from any app, and a clock when nothing is. It follows
          whichever DAC is playing, or one you pick (move the mouse). On a Linux machine with a monitor plugged in and
          no desktop, this sets it up to start at boot:

        


/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/meltface-80/Mandarin-DAC-Bridge/main/tools/linux/display.sh)"
# the bridge on another machine:  … display.sh)" -- --url http://192.168.1.20:55500/now
# remove it again:                 … display.sh)" -- --uninstall

      

    

  






  

    
Uninstall

    
Removing the bridge gives the DACs straight back to the machine and its apps. Point Audirvana
      and Mandarin at the DACs directly again afterwards.


    

      
      
      
      
    


    

      

        

/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/meltface-80/Mandarin-DAC-Bridge/main/tools/mac/uninstall.sh)"

      

      
It stops the bridge, removes it from login, and deletes ~/Mandarin-DAC-Bridge
        (the program, its settings and its log). Homebrew and ffmpeg stay, because Mandarin uses them too. If
        nothing else needs ffmpeg: brew uninstall ffmpeg.

      

        By hand instead
        

          

launchctl unload ~/Library/LaunchAgents/app.mandarin.dacbridge.plist
rm -f ~/Library/LaunchAgents/app.mandarin.dacbridge.plist
rm -rf ~/Mandarin-DAC-Bridge

        

      

    


    

      

        

powershell -ExecutionPolicy Bypass -c "irm https://raw.githubusercontent.com/meltface-80/Mandarin-DAC-Bridge/main/tools/windows/uninstall.ps1 | iex"

      

      
It stops the bridge, removes its scheduled task and firewall rule, and deletes
        %LOCALAPPDATA%\Mandarin-DAC-Bridge. ffmpeg stays; winget uninstall Gyan.FFmpeg removes it.

    


    

      

        

# Stop and remove the container, its image and its settings volume
docker stop mandarin-dac-bridge
docker rm mandarin-dac-bridge
docker rmi mandarin-dac-bridge
docker volume rm dac-bridge-data

      

      
Leave out the last line to keep the settings for a later reinstall.

    


    

      

        

# In the folder with the docker-compose.yml
docker compose down --rmi local --volumes

      

      
--volumes deletes the settings too; leave it out to keep them. Then delete the
        folder: cd .. && rm -rf mandarin-dac-bridge.

    

  






  

    
Settings

    
None are needed. On a DAC's page you can switch the bridge off for that DAC (it lets go and the
      machine can use it), choose how DSD files go (Auto, DoP or PCM), share it with other players while idle, and hand
      the DAC over to another app at once (Release). Squeezebox, Spotify, Qobuz, Plex and the Mac's apps are switched on
      under Connections.
      The rest are environment variables.

Troubleshooting

    
The log: ~/Mandarin-DAC-Bridge/data/bridge.log on a Mac,
      %LOCALAPPDATA%\Mandarin-DAC-Bridge\data\bridge.log on Windows,
      docker logs mandarin-dac-bridge in Docker.

    

      

        
A tile says "Waiting"

        
Another app has the DAC

        
The page names the app. Point it at the bridge's UPnP device instead, or quit it; the bridge takes the
          DAC within two seconds.

      

      

        
No "(Bridge)" devices in the apps

        
Discovery can't get through

        
The bridge and the apps must be on the same network. On a Mac, allow mandarin-dac-bridge under System
          Settings → Privacy & Security → Local Network. In Docker, use --network host. On a machine
          with several networks, set BRIDGE_IP.

      

      

        
"Transport is locked"

        
The other app is playing

        
That's the bridge keeping the apps apart. Stop the one playing (it keeps the DAC 10 seconds), or press
          Release on the DAC's page.

      

      

        
No DACs in Docker

        
The container can't see /dev/snd

        
Check cat /proc/asound/cards on the host lists the DAC, and that the command still has
          all three of --device /dev/snd, --privileged and
          -v /dev/snd:/dev/snd. docker exec mandarin-dac-bridge /app/mandarin-dac-bridge --diagnose
          shows what the container sees.

      

      

        
The Music app plays, the DAC is silent

        
macOS isn't letting the bridge read DAC Bridge

        
Allow mandarin-dac-bridge under System Settings → Privacy & Security → Microphone. Check that the
          Mac's sound output is DAC Bridge. mandarin-dac-bridge --loopback-test checks the output gives
          back exactly what it gets.
